# Structure and configuration

- Creating an environment for the project

- Creation
```bash
python -m venv .venv
```

- Activating the virtual environment
```bash
.venv\Scripts\Activate.ps1
```

- Deactivating the virtual environment
```bash
deactivate
```

### psycopg configuration

- Configuration for communicating with the db

1. Install the dependencies (listed in `requirements.txt`)
```bash
pip install -r requirements.txt
```
- `psycopg[binary]`: the PostgreSQL driver (the binary build avoids installing libpq manually)
- `python-dotenv`: loads the variables from the `.env` file

2. Create a `.env` file at the project root with the connection settings
```env
DB_NAME=database_name
DB_USER=user
DB_PASSWORD=password
DB_HOST=localhost
DB_PORT=5432
```
> Never commit the `.env`: add it to `.gitignore`.

3. Create the `users` table in PostgreSQL
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) NOT NULL,
    last_name VARCHAR(100),
    role VARCHAR(50)
);
```

## Implementation

### Project structure
```
demo-psycopg-en/
├── .env
├── requirements.txt
├── main.py                        # console menu
├── db/
│   └── db.py                      # db connection
└── repository/
    └── users_repository.py        # SQL queries (CRUD)
```

### 1. The connection: `db/db.py`
- `load_dotenv()` loads the `.env`, then `os.getenv(...)` reads each variable
- `get_connection()` returns a connection through `psycopg.connect(...)`
- `autocommit=True`: each query is committed right away, no need for `conn.commit()`

```python
def get_connection():
    return psycopg.connect(
        dbname=os.getenv("DB_NAME"),
        user=os.getenv("DB_USER"),
        password=os.getenv("DB_PASSWORD"),
        host=os.getenv("DB_HOST"),
        port=os.getenv("DB_PORT"),
        autocommit=True
    )
```

### 2. The repository: `repository/users_repository.py`
Each function receives the connection, opens a cursor with `with conn.cursor() as cursor:` (closed automatically), runs the query and returns the result.

| Function | Query | Returns |
|---|---|---|
| `get_all_users(conn)` | `SELECT * FROM users` | list of tuples (`fetchall()`) |
| `get_user_by_id(conn, id)` | `SELECT ... WHERE id = %s` | a tuple or `None` (`fetchone()`) |
| `create_user(conn, email, lastname, role)` | `INSERT ... RETURNING id` | the new id |
| `update_user(conn, email, lastname, id)` | `UPDATE ... WHERE id = %s` | number of rows (`rowcount`) |
| `delete_user(conn, id)` | `DELETE ... WHERE id = %s` | number of rows (`rowcount`) |

- Parameterized queries: use `%s` and pass the values in a tuple → protects against SQL injection
```python
cursor.execute("SELECT * FROM users WHERE id = %s", (id,))
```
> Careful: `(id,)` needs the comma, otherwise it is not a tuple.
- Never build the query with an f-string (`f"... WHERE id = {id}"`)
- `RETURNING id` gets back the id generated by PostgreSQL during the `INSERT`

### 3. The menu: `main.py`
- `with get_connection() as conn:` opens the connection once and closes it on exit
- A `while` loop displays the menu, `match choice:` calls the right repository function
- Choice `6` sets `continue_app` to `False` to quit

## Running the demo

1. Start PostgreSQL and check that the `users` table exists
2. Activate the virtual environment
```bash
.venv\Scripts\Activate.ps1
```
3. Run the application
```bash
python main.py
```
4. Demo scenario:
   - `3` create a user → prints the new id
   - `1` list users → the new user shows up
   - `2` look up by id
   - `4` update the email / last name → prints the number of rows updated
   - `5` delete → prints the number of rows deleted
   - `6` quit
